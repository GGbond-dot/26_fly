# fire_vision_pkg — 红色火花图案检测 + 火源地面坐标反投影（2023 电赛 G 题）

下视相机找火源，把像素位置反投影成 **map 系地面坐标**给 `fire_control_pkg`。
对应发挥部分 1（识别确认 + LED 报警，8 分）和 2（抛包 + 上报坐标，12 分）。

## 目标判定：不做筛选

场上三个火花图案中**只有目标是红色**，另两个是其它颜色。所以本包不做"哪个才是目标"的判断——
检测到红色即认定为目标。另外两个图案反而是现场标阈值时最好的**反例样本**：
确认它们不会被判成红即可。

## 三个关键设计

### 1）不用亮度门控，主判据是 LAB 的 a 通道

火源从"电池供电的红色 LED"降级成**印刷图案**后就是被动反光的，亮度随环境光走
（题目明说有顶部照明 + 窗外自然光 + 光照不均）。所以：

- **LAB 的 a 通道**（偏红程度）做主判据，对光照不均比 HSV 色相稳
- HSV 的 **S** 做二次确认——淡灰底布 (240,240,240) 的 S≈0，
  淡蓝坐标线 (180,230,255) 色相在另一头，光这一条就能把整个场地背景干掉
- V 只用来去掉纯黑

### 2）必须锁白平衡

自动白平衡会让红色随光照漂移，**实验室标好的阈值搬到现场就废了**。
开相机时关掉 `CAP_PROP_AUTO_WB` / `CAP_PROP_AUTO_EXPOSURE`；
有些 UVC 驱动不支持，关不掉会 WARN——那就只能在现场实际光照下重标。

### 3）最大的误检源是红色消防车停车区

它和火源图案同色，但 18dm 高度下面积差 25 倍以上（5dm vs ~1dm）。三重防线：

| 防线 | 参数 | 说明 |
|---|---|---|
| 面积上下限 | `min_area_px` / `max_area_px` | 第一道，挡大色块 |
| 形状过滤 | `min_fill_ratio` / `max_aspect_ratio` | 挡细长条、破碎区域 |
| **几何黑名单** | `blacklist_dm` | **最可靠**——起降区/停车区坐标已知，落在里面直接丢 |

> ⚠️ **黑名单宁可框小也不要框大。** 左下那个街区是 x6~15 / y7~20（见车端 `obstacles_dm`），
> 火源就放在街区里——黑名单一旦盖到 y>7，街区下边缘的火源会被误丢，直接丢 20 分。
> 默认值已按题目图 1 严格贴着两块实际区域框：
> `[0,0,11,7]`（起降区）+ `[11,0,16,5]`（停车区）。
> 漏挡最多多一次误检（还有面积过滤和多帧投票兜着），框大是直接丢分。

### 多帧投票

单帧误检（顶部照明反光、评委的红衣服飘过视野）不予采信：
最近 `vote_window` 帧里至少 `vote_min` 帧检测到，**且**位置抖动在 `vote_jitter_cm` 内，
才发 `/fire/position_map`。

## 反投影

相机垂直向下，针孔模型：

```
dx_img = (u - cx) * h / fx        # 图像"右"方向的地面偏移
dy_img = (v - cy) * h / fy        # 图像"下"方向的地面偏移
```

再按 `cam_yaw_offset_deg` 转到机体系（REP-103：+x 前，+y 左）、
按当前 yaw 转到 map 系、加上无人机自身位置和相机安装偏移。

**约定**：`cam_yaw_offset_deg = 0` 时，图像"上"(-v) 对应机体 **+x**（机头前方），
图像"右"(+u) 对应机体 **-y**（机身右侧）。装反了整个方向就错，
第一次试飞务必用"把图案放在机头正前方，看报出来的坐标是不是在飞机前方"验证。

## 接口

| 方向 | Topic | 类型 | 说明 |
|------|-------|------|------|
| 发布 | `/fire/detected` | Bool | 本帧是否看到红色（**原始，未投票**），仅供观察 |
| 发布 | `/fire/position_map` | Float32MultiArray | `[x_cm, y_cm]`，**map 系**，已投票确认 |
| 发布 | `/fire/debug_image` | Image | 调试图（`enable_debug_image` 时） |
| 订阅 | `/fire/enable` | Bool | 检测总开关，默认 True |
| 订阅 | `/height` | Int16 | 离地高度 cm，反投影必需 |
| tf | `map → laser_link` | — | 无人机位姿 |

`fire_control_pkg` 收到 `/fire/position_map` 后还会再做一层位置稳定性判定
（`fire_confirm_sec` / `fire_position_jitter_dm`），两层串联。

## 现场标定（**必做，否则拿不到分**）

### 1. 颜色阈值 — 用配套工具

```bash
ros2 run fire_vision_pkg fire_color_tune
```

把相机举到 18dm 左右对着图案，拖滑块直到**只有火花图案是白的，
底布/坐标线/街区/红色停车区全黑**。按 `p` 打印参数，直接粘进 launch 文件。

**务必把另外两个非红图案也放进视野**确认它们不亮——这是最好的反例。

### 2. 相机内参 — 棋盘格标定

`fx_px`/`fy_px` 不给时按 `hfov_deg` 粗推，**只够把流程跑通**。
反投影误差直接变成火源坐标误差，而**抛包判定半径只有 3dm**：
18dm 高度下 1° 的角度误差就是约 3cm 的地面误差，累积起来很容易出圈。

### 3. 相机安装方位

确认 `rotate_code` 让画面转正，确认 `cam_yaw_offset_deg` 的方向约定成立。

## 运行

```bash
ros2 launch fire_vision_pkg fire_vision.launch.py

# 带预览窗（需 DISPLAY，远程调试用；比赛时关掉）
ros2 launch fire_vision_pkg fire_vision.launch.py enable_gui:=true
```

不用飞就能验证反投影：把飞机架在已知高度和位置，把图案放在地面已知点，
看 `/fire/position_map` 报出来的坐标对不对。

```bash
ros2 topic echo /fire/position_map
```
